# Reproducing the simulation inputs

This directory makes the force fields, stage settings and archived examples easy to find. It does not contain complete trajectories or every executed job. The manuscript used GROMACS 2022.1 with PLUMED 2.8, Cassandra 1.3.1, mBuild/Foyer, MoSDeF-Cassandra and the Signac workflow; dependency/environment files and project generators remain in the repository root and the original project directories.

## Parameter files

Use [Opt_ES/FF_params](../Opt_ES/FF_params/README.md) to choose a named molecule and variant. `manifest.json` records the exact validation-table vector. Both variants are included; the recommended model differs by molecule. Verify files using `python3 reproducibility/check_inputs.py` from the repository root. This only reads inputs and performs numerical consistency checks.

## GROMACS stage inputs

`examples/EG_GP-Optimized_393.15K` and `examples/DEC_Base_353.19K` copy the archived `.mdp`, processed `mdout.mdp`, force field, topology, state point and job document for two actual validation jobs. Their source paths are in `examples/manifest.json`. The copied DEC XML receives the same ampersand-encoding repair described in the parameter README; MDPs remain exact copies. Coordinates for every stage and the complete continuation histories are not available in this package, so these collections do not constitute standalone restarts. The original workspace files remain unchanged.

`templates/gromacs/*.mdp.template` expose the same settings with explicit markers for state-dependent temperature, pressure and interface cutoff. Replace every `@MARKER@` before using a template. For NPzzAT, `@ZERO_XY_AND_PZZ_BAR@` means the three-value pressure vector `0 0 Pzz`; the high-pressure compression stage uses Pzz=5Pvap and the separate density equilibration/production stages use Pzz=Pvap. Do not treat markers as valid GROMACS values.

| Stage | Purpose | Input configuration |
|---|---|---|
| `em` | Minimize initially packed elongated liquid | Configuration generated by mBuild/Packmol |
| `nvt_eq` | Initial 100 ps equilibration | Minimized configuration |
| `npzzat_eq` | Compression at Pzz=5Pvap | NVT configuration |
| `npzzat_eq_pvap` | Separate density equilibration at Pzz=Pvap | NVT configuration |
| `npzzat_prod` | Separate 2.5 ns density production | Saturated-density equilibration configuration |
| `inter_eq` | 40 ns slab equilibration after tripling volume along z | Volume-quenched compressed-liquid configuration |
| `inter_prod` | 40 ns surface-tension production | Equilibrated slab configuration |

The generator in `Opt_ES/ift_val_opt/project.py` (and its Base counterpart) supplies packing, volume quench, equilibration-extension/checkpoint logic and analysis. Inspect its operations and the saved state point before reproducing a specific job. The historical initializers create many jobs; narrow molecule, temperature and variant selection before invoking them. Do not run a whole project merely to recover one input.

With complete coordinates and a matching molecule count, the ordinary single-stage GROMACS preparation pattern is:

```sh
gmx grompp -f STAGE.mdp -c PREVIOUS_STAGE.gro -p system.top -o STAGE.tpr
gmx mdrun -deffnm STAGE
```

These commands are documented for future reproducibility; they were not executed when preparing this package. Check preparation diagnostics rather than blindly reproducing the generator's permissive `-maxwarn 5`. Complete historical continuation and equilibration logic is in `project.py`; a stage list alone cannot reproduce all extended runs.

## Long-range interactions and geometry

The saved GROMACS interface inputs use **electrostatic PME**, fourth-order interpolation, Fourier spacing 0.16 nm, Ewald tolerance 1e-5 and periodicity in x/y/z. They use **LJ Cut-off**, `vdw-modifier=None` and `DispCorr=no`. Processed inputs set `ewald-geometry=3d` and `epsilon-surface=0`; these examples do not use the `3dc` slab correction. No LJ-PME was used. Bulk/density setup stages use a 1.2 nm cutoff and `DispCorr=EnerPres`.

For interfaces, the generator chooses

```text
cutoff_nm = min(round(0.475 * min(xy_length_nm, z_length_nm), 5),
                round(6 * max_sigma_bound_nm, 5))
```

The state-point field `max_sigma` is initialized from the largest sigma optimization upper bound, rather than the largest fitted sigma. Both archived example jobs store 0.4 nm, giving a 2.4 nm cap. This cutoff is governed by the shorter box dimension and the cap; it is not 47.5% of the elongated vapor/slab box length. The same real-space cutoff is assigned to LJ and Coulomb interactions, with long-range Coulomb terms still evaluated by PME. These inputs establish what was used; they do not provide a comparison demonstrating cutoff, slab-electrostatics or LJ-PME convergence.

## Cassandra settings and unavailable inputs

`templates/cassandra/settings.json` is a documented **generator-settings template**, not a runnable Cassandra `.inp`. It records `_get_custom_args` and the GEMC stage settings from `Opt_ES/gemc_val_opt/project.py`. The original generated Cassandra `.inp` files and fragment libraries are not present in the locally archived validation examples. They must be generated through the existing MoSDeF-Cassandra workflow or recovered from the cluster archive; no substitute execution files are invented here.

Cassandra uses Ewald electrostatics (`ewald_accuracy=1e-5`), LJ `cut_tail`, Lorentz-Berthelot mixing, and a 12 angstrom cutoff in the liquid box. Before each GEMC stage the vapor cutoff is set to 0.475 times the pre-GEMC vapor-box edge; the cap used for GROMACS interfaces is not active in this Cassandra expression. The code updates settings from the initialization/restart box and records the selected vapor cutoff in the job document; do not infer that it was continuously recalculated as the GEMC box exchanged volume.

The nominal sequence is liquid NVT (2,500 sweeps), liquid NPT at RD2 Pvap (5,000 sweeps), two-box GEMC equilibration (50,000 sweeps) and GEMC production (100,000 sweeps). A sweep is 640 trial moves in single-box initialization and 800 trial moves in GEMC. The production GEMC ensemble fixes total N and total V at T and does not impose the initialization pressure. Automatic checks/restarts can extend equilibration and change failed initializations, so use the project code and job record to reconstruct the complete run.

Actual locally archived Cassandra example parameter/state-point files are in:

- `Opt_ES/gemc_val_opt/workspace/00ad476c7aa5d3e37d3297d989576bd8` (DMF GP-Optimized, 308.15 K; includes a failed/unstable vapor attempt and is not evidence of successful VLE validation).
- `Opt_ES/gemc_val_no_opt/workspace/0b6a289cb7b8f0c44f4d79d5b388097c` (MeOH Base, 500 K).

Additional full-precision parameter vectors for both variants of all six molecules are in the validation CSVs referenced by `Opt_ES/FF_params/manifest.json`. Availability of a parameter export does not imply successful vapor-property validation for that molecule.
